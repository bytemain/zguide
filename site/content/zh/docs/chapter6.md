# 第 6 章 ZeroMQ 社区

## 架构

ZeroMQ 社区由一组松散连接的组织和个人组成，他们共同致力于 ZeroMQ 软件及其生态系统。这些组织和个人通常使用 ZeroMQ 作为其业务或开源项目的一部分，并且出于各种原因希望 ZeroMQ 能够蓬勃发展。

社区由多个部分组成：

- 邮件列表（zeromq-dev）
- 聊天室（#zeromq on libera.chat）
- 年度聚会（ZeroMQ 开发者聚会）
- 代码仓库（github.com/zeromq）
- 文档（zguide.zeromq.org）
- 维基（github.com/zeromq/zguide/wiki）
- 问题跟踪器（github.com/zeromq/libzmq/issues）

社区没有中央权威。每个项目都是自主的，由维护者团队管理。维护者通过向贡献者提供提交访问权限来扩展团队。贡献者通过向维护者发送补丁来成为提交者。维护者通过向其他维护者发送拉取请求来做出决策。

社区使用 Collective Code Construction Contract（C4）流程来管理变更。C4 是一个轻量级的、基于共识的流程，强调：

- 及早发布，经常发布
- 通过拉取请求接受补丁
- 快速合并（无讨论）
- 通过回滚而不是讨论来解决问题
- 通过实验而不是讨论来做出决策

## 开源模型

ZeroMQ 社区基于开源模型，这意味着：

- 软件是免费提供的
- 源代码是公开的
- 任何人都可以贡献
- 决策是公开做出的
- 项目是自我管理的

开源模型有几个优势：

- **质量**：更多的人可以审查和改进代码
- **创新**：更多的人可以尝试新想法
- **可持续性**：项目不依赖于任何个人或组织
- **采用**：免费软件更容易被采用
- **生态系统**：开源项目创建生态系统

然而，开源模型也有一些挑战：

- **协调**：更难协调开发
- **质量**：更难确保质量
- **安全**：更难确保安全
- **可持续性**：更难确保可持续性
- **治理**：更难治理项目

ZeroMQ 社区通过使用 C4 流程来解决这些挑战，该流程提供了一个轻量级但有效的治理模型。

## C4 流程

Collective Code Construction Contract（C4）是一个用于管理开源项目的流程。它基于以下原则：

1. **及早发布，经常发布**：变更应该快速合并和发布
2. **通过拉取请求接受补丁**：所有变更都应该通过拉取请求
3. **快速合并**：拉取请求应该在 24 小时内合并
4. **通过回滚而不是讨论来解决问题**：有问题的变更应该被回滚，而不是讨论
5. **通过实验而不是讨论来做出决策**：决策应该通过实验，而不是讨论

C4 流程如下工作：

1. 贡献者创建一个拉取请求
2. 维护者审查拉取请求
3. 如果拉取请求没问题，维护者合并它
4. 如果拉取请求有问题，维护者回滚它
5. 如果拉取请求有争议，贡献者创建一个新的拉取请求

C4 流程有几个优势：

- **速度**：变更可以快速合并
- **质量**：问题可以快速修复
- **创新**：新想法可以快速尝试
- **可持续性**：项目不依赖于任何个人
- **治理**：流程是轻量级和透明的

然而，C4 流程也有一些挑战：

- **协调**：更难协调大的变更
- **质量**：更难确保质量
- **安全**：更难确保安全
- **可持续性**：更难确保可持续性
- **治理**：流程可能过于轻量级

ZeroMQ 社区通过使用额外的流程来解决这些挑战，如 RFC 流程用于大的变更，以及安全流程用于安全问题的处理。

## Git 工作流程

ZeroMQ 社区使用 Git 进行版本控制，工作流程如下：

1. **主分支**：主分支始终是稳定的
2. **功能分支**：新功能在功能分支中开发
3. **拉取请求**：变更通过拉取请求合并
4. **代码审查**：所有变更都经过代码审查
5. **持续集成**：所有变更都经过持续集成

工作流程如下工作：

1. 贡献者从主分支创建功能分支
2. 贡献者在功能分支中进行变更
3. 贡献者创建拉取请求
4. 维护者审查拉取请求
5. 如果拉取请求没问题，维护者合并它
6. 如果拉取请求有问题，维护者回滚它

工作流程有几个优势：

- **质量**：所有变更都经过代码审查
- **稳定性**：主分支始终是稳定的
- **协作**：多人可以同时工作
- **可追溯性**：所有变更都是可追溯的
- **可重现性**：所有版本都是可重现的

然而，工作流程也有一些挑战：

- **复杂性**：工作流程可能很复杂
- **开销**：工作流程可能有开销
- **协调**：更难协调大的变更
- **质量**：更难确保质量
- **安全**：更难确保安全

ZeroMQ 社区通过使用自动化工具来解决这些挑战，如持续集成和自动化测试。

## 避免倦怠

倦怠是开源社区中的常见问题。ZeroMQ 社区使用几种策略来避免倦怠：

1. **轮换**：维护者轮换责任
2. **授权**：维护者授权给他人
3. **自动化**：维护者自动化任务
4. **文档**：维护者记录流程
5. **支持**：维护者相互支持

策略如下工作：

2. 维护者授权给他人以分担工作

策略有几个优势：

- **质量**：质量得到维持

- **采用**：采用得到维持
- **生态系统**：生态系统得到维持

## 总结
