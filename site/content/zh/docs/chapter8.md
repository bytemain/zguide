# 分布式计算框架

我们已经经历了理解 ZeroMQ 各个方面的旅程。到目前为止，你可能已经开始使用我解释的技术以及你自己想出的技术来构建自己的产品。你将开始面临如何使这些产品在现实世界中工作的问题。

但是那个"现实世界"是什么？我认为它正成为一个越来越多移动部件的世界。有些人使用"物联网"这个短语，暗示我们将看到一类新的设备，这些设备比我们当前的智能手机、平板电脑、笔记本电脑和服务器更众多但也更愚蠢。然而，我完全不认为数据指向这个方向。是的，设备越来越多，但它们一点也不愚蠢。它们聪明而强大，并且越来越如此。

起作用的是我称之为"成本重力"的机制，它的效果是将技术的成本每 18-24 个月减少一半。换句话说，我们的全球计算能力每两年翻一番，一遍又一遍。未来充满了数万亿的设备，这些设备都是功能强大的多核计算机：它们不运行简化的"物品操作系统"，而是完整的操作系统和完整的应用程序。

这就是我们用 ZeroMQ 针对的世界。当我们谈论"规模"时，我们不是指数百台计算机，甚至不是数千台。想想围绕着每个人的微小智能且可能自我复制的机器云，填充每个空间，覆盖每面墙，最终成为我们的一部分，以至于我们在出生前就得到它们，它们跟随我们直到死亡。

这些微小的机器云彼此交谈，始终通过短距离无线链路使用互联网协议。它们创建网状网络，像神经信号一样传递信息和任务。它们增强我们的记忆、视觉、我们交流的每个方面以及身体功能。正是 ZeroMQ 为它们的对话、事件以及工作和信息的交换提供动力。

现在，为了使这一切在今天哪怕只是薄弱的模仿成为现实，我们需要解决一系列技术问题。这些包括：对等方如何发现彼此？它们如何与现有网络（如 Web）交谈？它们如何保护它们携带的信息？我们如何跟踪和监控它们，以了解它们在做什么？然后我们需要做大多数工程师忘记的事情：将这个解决方案打包成一个框架，让普通开发者能够轻松使用。

这就是我们在本章中尝试做的事情：构建一个分布式应用程序的框架，作为 API、协议和实现。这不是一个小挑战，但我经常声称 ZeroMQ 使这样的问题变得简单，所以让我们看看这是否仍然正确。

我们将涵盖：

* 分布式计算的需求
* WiFi 用于邻近网络的优缺点
* 使用 UDP 和 TCP 的发现
* 基于消息的 API
* 创建一个新的开源项目
* 点对点连接（和谐模式）
* 跟踪对等方的存在和消失
* 无需中央协调的群组消息传递
* 大规模测试和仿真
* 处理高水位标记和阻塞的对等方
* 分布式日志记录和监控

## 为现实世界设计

无论我们是通过 WiFi 连接房间里的移动设备，还是通过模拟以太网连接虚拟盒子集群，我们都会遇到同样的问题。这些问题是：

* //发现//：我们如何了解网络上的其他节点？我们使用发现服务、集中式中介，还是某种广播信标？

* //存在//：我们如何跟踪其他节点的来去？我们是否使用某种中央注册服务，或心跳或信标？

* //连接//：我们如何实际将一个节点连接到另一个节点？我们是否使用本地网络、广域网络，还是使用中央消息代理进行转发？

* //点对点消息传递//：我们如何从一个节点向另一个节点发送消息？我们是否将此消息发送到节点的网络地址，还是通过中央消息代理使用某种间接寻址？

* //群组消息传递//：我们如何从一个节点向一组其他节点发送消息？我们是否通过中央消息代理工作，还是使用像 ZeroMQ 这样的发布 - 订阅模型？

* //测试和仿真//：我们如何仿真大量节点，以便我们可以正确测试性能？我们是否必须购买两打 Android 平板电脑，还是可以使用纯软件仿真？

* //分布式日志记录//：我们如何跟踪这云节点在做什么，以便我们可以检测性能问题和故障？我们是否创建主日志服务，还是允许每个设备记录它周围的世界？

* //内容分发//：我们如何从一个节点向另一个节点发送内容？我们是否使用服务器中心协议如 FTP 或 HTTP，还是使用去中心化协议如 FileMQ？

如果我们能够合理地解决这些问题，以及将会出现的进一步问题（如安全性和广域网桥接），我们就得到了我可能会称之为"真正酷的分布式应用程序"框架的东西，或者我的孙子孙女们称之为"我们的世界运行的软件"。

你应该从我的修辞问题中猜到，我们可以朝两个广泛的方向发展。一个是将一切集中化。另一个是将一切分布式化。我将押注于去中心化。如果你想要集中化，你真的不需要 ZeroMQ；你可以使用其他选项。

所以非常粗略地说，故事是这样的。首先，移动部件的数量随时间呈指数增长（每 24 个月翻一番）。其次，这些部件停止使用电线，因为拖着电缆到处走变得//真的//无聊。第三，未来的应用程序使用来自 [#the-community] 的仁慈暴君模式在这些部件集群上运行。第四，今天构建这样的应用程序真的很难，nay 仍然相当不可能。第五，让我们使用我们积累的所有技术和工具使其变得便宜和简单。第六，派对！

## WiFi 的秘密生活

未来显然是无限的，虽然许多大企业靠将其数据集中在他们的云中生存，但未来看起来并不那么集中化。网络边缘的设备每年变得越来越智能，而不是越来越愚蠢。它们渴望工作和信息来消化，并从中获利。它们不会拖着电缆到处走，除了每天晚上充电一次。这一切都是无线的，越来越多的是 802.11 品牌的不同字母风味的 WiFi。

### 为什么网状网络还没有出现

作为我们未来如此重要的一部分，WiFi 有一个大问题，这个问题不经常被讨论，但任何押注于它的人都需要意识到。世界上的电话公司已经在几乎每个有运作政府的国家建立了漂亮的有利可图的移动电话卡特尔，基于说服政府，如果没有对电波和思想的垄断权，世界就会崩溃。技术上，我们称这为"监管捕获"和"专利"，但实际上它只是一种勒索和腐败的形式。如果你，国家，给我，一个企业，给予我过高收费、对市场征税和禁止所有真正竞争者的权利，我会给你 5%。不够？那 10% 怎么样？好的，15% 加零食。如果你拒绝，我们就停止服务。

但 WiFi 潜入了这一点，借用了未经许可的空白空间，并建立在开放且未申请专利且非常创新的互联网协议栈的背上。所以今天，我们有一个奇怪的情况，如果我使用我们几十年来一直补贴的国家支持的基础设施从首尔打电话到布鲁塞尔，每分钟要花费我几欧元，但如果我能找到一个不受监管的 WiFi 接入点，就根本不需要任何费用。哦，我还可以做视频、发送文件和照片，并下载整个家庭电影，所有这些的价格都是精确的零点零零（任何你喜欢的货币）。如果我尝试使用我实际付费的服务发送一张照片回家，那就帮帮我吧。这将花费我比我在上面拍摄的相机更多的钱。

这是我们长期以来容忍"相信我们，我们是专家"专利制度所付出的代价。但更重要的是，这对技术行业的某些部分——尤其是拥有反互联网 GSM、GPRS、3G 和 LTE 栈专利的芯片制造商，以及将电信公司视为主要客户的芯片制造商——构成了巨大的经济激励，积极阻碍 WiFi 的发展。当然，正是这些公司充实了定义 WiFi 的 IEEE 委员会。

这次对律师驱动的"创新"的咆哮是为了引导你的思维朝着"如果 WiFi 真的免费会怎样？"这一方向。这一天会到来，不会太远，值得押注。我们将看到几件事情发生。首先，更积极地使用空白空间，特别是对于近距离通信，因为没有干扰风险。其次，随着我们学会并行使用更多空白空间，容量大幅提升。第三，标准化进程加速。最后，设备对真正有趣的连接性的支持更加广泛。

现在，从手机向电视播放电影被认为是"领先边缘"。这太荒谬了。让我们真正雄心勃勃一点。一个体育场的人观看比赛，实时互相分享照片和高清视频，创建一个临时的活动，字面上使空白空间充满数字狂潮。我应该能够在小时内从周围的人那里收集 TB 级的图像。为什么这必须通过 Twitter 或 Facebook 以及那微小昂贵的移动数据连接？一个家庭有数百个设备通过网状网络互相交谈，所以当有人按门铃时，门廊灯将视频流式传输到你的手机或电视？一辆车可以与你的手机交谈，并播放你的 dubstep 播放列表//而无需你插入电线//。

说得更严肃些，为什么我们的数字社会掌握在可以被监控、审查、记录、用来追踪我们与谁交谈、收集对我们不利的证据，然后在当局决定我们有太多言论自由时关闭的中央点手中？我们正在经历的隐私损失只有当它是单方面的时候才是问题，但那时问题就是灾难性的。一个真正无限的世界将绕过所有中央审查。这就是互联网的设计方式，它在技术上是相当可行的（这是最好的可行方式）。

### 一些物理学

天真的分布式软件开发人员将网络视为无限快速且完全可靠。虽然对于以太网上的简单应用程序这大致正确，但 WiFi 在压力下如此容易且戏剧性地破坏，以至于我有时想知道任何人如何敢于将其用于真正的工作。随着 WiFi 变得更好，天花板会向上移动，但永远不会足够快以阻止我们撞到它。

要理解 WiFi 在技术上的表现，你需要理解一条基本物理定律：连接两点所需的功率根据距离的平方增加。在达拉斯长大的房子里长大的人说话的声音呈指数级增大，正如我在达拉斯了解到的那样。对于 WiFi 网络，这意味着随着两个无线电设备相距越来越远，它们必须要么使用更多功率，要么降低信号速率。

你可以从电池中汲取的功率是有限的，然后用户会将该设备视为无可救药地损坏。因此，即使 WiFi 网络可能以某个速度评级，接入点（AP）与客户端之间的实际比特率取决于两者相距多远。当你将支持 WiFi 的手机从 AP 移开时，两个试图互相交谈的无线电设备首先会增加功率，然后降低比特率。

这种效应有一些后果，如果我们想要构建不像木偶一样在身后拖着电线的健壮的分布式应用程序，我们应该意识到这些后果：

* 如果你有一组设备与 AP 交谈，当 AP 与最慢的设备交谈时，//整个网络必须等待//。这就像在聚会上不得不向指定司机重复一个笑话，这个司机没有幽默感，仍然完全而悲惨地清醒，并且对语言掌握得很差。

* 如果你使用单播 TCP 并向多个设备发送消息，AP 必须单独向每个设备发送数据包。是的，你知道这一点，这也是以太网的工作原理。但现在要明白，一个遥远的（或低功耗）设备意味着所有东西都在等待那个最慢的设备赶上。

* 如果你使用多播或广播（在大多数情况下工作方式相同），AP 将立即向整个网络发送单个数据包，这很棒，但它会以尽可能慢的比特率（通常为 1Mbps）进行。你可以在 some AP 中手动调整此速率。这只减少了你的 AP 的覆盖范围。你还可以购买更昂贵的 AP，这些 AP 有更多的智能，会找出它们可以安全使用的最高比特率。你还可以使用支持 IGMP（互联网组管理协议）和 ZeroMQ 的 PGM 传输的企业 AP，仅发送到订阅的客户端。然而，我不会押注这样的 AP 会广泛可用，永远不会。

当你尝试将更多设备放到 AP 上时，性能会迅速恶化，以至于添加一个更多设备可能会为每个人破坏整个网络。许多 AP 通过在有客户端时随机断开连接来解决这个问题，例如移动热点的 4 到 8 个设备，消费 AP 的 30-50 个设备，企业 AP 的 100 个设备。

### 当前状况如何？

尽管 WiFi 作为不知何故逃到野外的企业技术的角色令人不舒服，但 WiFi 已经不仅仅用于免费 Skype 通话。它不是理想的，但它足够好，让我们解决一些有趣的问题。让我给你一个快速的状态报告。

首先，点对点与接入点到客户端。传统 WiFi 都是 AP-客户端。每个数据包都必须从客户端 A 到 AP，然后到客户端 B。你将带宽削减了 50%，但这只是问题的一半。我解释了逆幂定律。如果 A 和 B 非常接近，但两者都远离 AP，它们都将使用低比特率。想象一下你的 AP 在车库，而你在客厅试图从手机向电视播放视频。祝你好运！
